# ROADMAP — Console 1.0

Решение: сначала доводим **консольную систему** до состояния «ставится на реальный ПК и пригодна как домашний сервер», и только потом — 3D (kmscube/glmark2 через DRM/KMS) и графическая оболочка.
Decision: finish the **console system** first; 3D and a graphical shell come after Console 1.0.

**Критерий готовности Console 1.0:** образ ставится с USB на реальный UEFI-ПК, грузится, доступен по SSH, умеет раздавать файлы, обновляться и запускать сторонние программы; всё это проверяется автоматически в CI (QEMU).

## M0. Стабильность и проверка (первым делом)
- [ ] Зелёный прогон CI: сборка + загрузка полного и lite образов в QEMU/OVMF.
- [ ] Автоматическая установка для тестов: `hs-install --disk DEV --yes` (без диалогов) + serial-шелл только для тестового образа.
- [ ] CI-тест «установка → перезагрузка с установленного диска → метка загрузки» (вторая виртуальная диск в QEMU).
- [ ] shellcheck/`sh -n` для overlay, проверка размеров, SHA256SUMS в релизе.
- [ ] Проверка на реальном ПК (ваш отчёт: какой экран/ошибка).

## M1. Пользователи и безопасность
- [ ] Обычный пользователь (по умолчанию `admin`) + `su`/`doas`; root-логин по SSH выключен по умолчанию.
- [ ] SSH: вход по ключу как рекомендуемый режим, сохранение host-ключей на диск, блокировка перебора (задержка).
- [ ] Простой файрвол (iptables/nftables, если собирается статически): профили «закрыто / SSH+Web / открыто».
- [ ] Смена пароля, политика паролей, экран входа с IP-адресом.

## M2. Хранилище и данные
- [ ] Мастер «подключить второй диск»: разметка, ext4, автомонтирование (`/etc/fstab` или `hs-mounts`), метки.
- [ ] Проверка здоровья дисков (smartmontools, статически), температуры в дашборде.
- [ ] Сетевые папки: SMB (Samba или лёгкая альтернатива) и/или FTP (busybox `ftpd`), мастер «создать общую папку».
- [ ] Резервная копия конфигурации `/etc/hs` в архив и восстановление.

## M3. Сторонние программы (`hs-get`)
- [ ] `hs-get URL [sha256]`: скачивание по HTTPS, проверка суммы, установка в `/opt/apps`, ярлык в `PATH`.
- [ ] Каталог проверенных программ (файл списка с URL и sha256): fastfetch, ncdu, tmux, htop-подобное и т.д.
- [ ] Совместимость с glibc-бинарниками: кэш `ld.so.cache`, набор базовых библиотек в полном образе.
- [ ] Запуск от обычного пользователя; предупреждение при запуске от root.

## M4. Сеть
- [ ] Wi-Fi (wpa_supplicant + выбор сети в TUI; прошивки — по желанию пользователя, не в образе).
- [ ] IPv6, DNS-настройки, проверка связи с понятными сообщениями.
- [ ] Имя в локальной сети (mDNS) — если удастся без тяжёлых зависимостей.

## M5. Обслуживание системы
- [ ] `hs-update`: скачать новый релиз (ядро + rootfs) из GitHub Releases, проверить sha256, заменить ядро на ESP и систему с откатом.
- [ ] Кнопка питания (acpid), корректное выключение; ротация логов; `logread` в меню.
- [ ] Несколько установок на одном ПК (сейчас PARTUUID вшит в ядро — продумать загрузку без этого ограничения).

## M6. Удобство
- [ ] Русский язык: раскладка консоли (loadkmap), кириллический шрифт, выбор языка в мастере, перевод меню (en/ru).
- [ ] Справка внутри системы, подсказки в меню, единый стиль экранов.
- [ ] Страница статуса по HTTP (`http://IP/`), показывающая сведения о сервере.

## После Console 1.0
1. 3D без оконной системы: kmscube / glmark2 через DRM/KMS (Mesa: llvmpipe или родной драйвер).
2. Графическая оболочка (Wayland: labwc или sway + foot).
3. Свой 3D-движок как отдельный проект поверх DRM/GBM/GLES.
FurMark: закрытый, требует X11/Wayland и драйвер GPU — после пункта 2; до этого заменяется glmark2.

## Порядок работы
M0 → M3 (даёт fastfetch и сторонние программы) → M1 → M2 → M5 → M6 → M4. Каждый пункт заканчивается проверкой в CI или в тестовом окружении.
