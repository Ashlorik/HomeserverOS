# HomeserverOS

**HomeserverOS** — это экспериментальная, полностью **созданная с помощью ИИ (AI-made)** минималистичная операционная система для домашних серверов. Она ориентирована на работу исключительно в текстовом (консольном) UEFI-режиме и собирается "с нуля" без использования тяжелых дистрибутивов и сторонних загрузчиков, обеспечивая мгновенную работу.

## 🚀 Основные особенности
* **Разработка ИИ:** Архитектура скриптов, конфигурация монолитного ядра и логика инициализации спроектированы и оптимизированы с помощью искусственного интеллекта.
* **Минимальный размер:** Сжатый архив занимает всего около **14 МБ**, разворачиваясь в сырой образ диска объемом 500 МиБ.
* **Современное ядро:** Используется монолитное ядро **Linux 6.12** (конфигурация без внешних модулей). В ядро встроены драйверы для SATA/AHCI, NVMe, USB-накопителей, MMC/SD, а также популярных сетевых карт (Intel, Realtek, Broadcom).
* **Легковесное окружение:** Статический **BusyBox**, утилита построения псевдографических меню `dialog`, системный монитор `btop` и консольный файловый менеджер `nnn`.
* **Загрузка без GRUB:** Ядро скомпилировано как полноценное UEFI-приложение (`EFI/BOOT/BOOTX64.EFI`), параметры командной строки (включая PARTUUID корневого раздела и кастомную темную палитру консоли) вшиты прямо в него.
* **Мастер настройки:** При первой загрузке на физической консоли запускается интерактивный TUI-wizard, который поможет задать имя сервера, сетевые настройки (DHCP или Static IP) и установить пароль администратора (`root`).

## 🛠️ Предварительные требования (Host Prerequisites)

Для ручной сборки проекта вам понадобится хост-система на базе Debian/Ubuntu. Установите необходимые зависимости одной командой:

```bash
sudo apt-get update && sudo apt-get install -y build-essential bison flex libssl-dev libncurses-dev libuuid-dev e2fsprogs dosfstools grub-pc-bin grub-efi-amd64 mtools xorriso busybox wget
```

## 📦 Структура репозитория

* `build.sh` — единый унифицированный Bash-скрипт автоматизации сборки, монтирования loop-устройств, компиляции ядра и BusyBox.
* `overlay/` — кастомное дерево каталогов, переносимое в корень (`etc/inittab`, профили, конфигурация сети, баннеры, настройки `btop` и `nnn`).
* `.config` — готовый рабочий файл конфигурации ядра Linux.
* `README.md` — руководство пользователя.

## 💾 Запись готового образа на диск

> ⚠️ **ВНИМАНИЕ:** Не перепутайте имя целевого устройства (вместо `sdX`), это действие полностью уничтожит данные на указанном накопителе!

Вы можете записать распакованный образ `homeserver.img` через графическую утилиту **balenaEtcher** или воспользоваться терминалом:

```bash
xz -dc homeserver.img.xz | sudo dd of=/dev/sdX bs=4M conv=fsync status=progress

# Необязательно: расширение разметки под диски большего размера
sudo sgdisk -e /dev/sdX     
```

### Настройки BIOS/UEFI:
В настройках вашей материнской платы обязательно **включите режим UEFI** и **отключите Secure Boot** (в данной редакции поддержка подписей Secure Boot не предусмотрена).

## 💻 Тестирование в виртуальной машине (QEMU)

### Windows: `run_qemu.bat` (launcher / запускатор)

EN: double-click `run_qemu.bat`. The menu lets you pick a local image or download one from the GitHub releases (SHA-256 is checked), choose UEFI or legacy BIOS boot, memory/CPUs, safe mode (changes discarded) or persistent disk, and test the installer on an empty virtual disk, then boot the installed system from it. QEMU and 7-Zip are installed through `winget` if missing. Settings are saved in `hs-launcher.json`.

RU: запустите `run_qemu.bat`. В меню: выбор образа из папки или скачивание из релизов GitHub (с проверкой SHA-256), загрузка через UEFI или BIOS, память и ядра, безопасный режим (изменения не сохраняются) или постоянный диск, проверка установщика на пустом виртуальном диске с последующей загрузкой установленной системы. QEMU и 7-Zip при отсутствии ставятся через `winget`. Настройки хранятся в `hs-launcher.json`.


Если вы хотите протестировать работу ОС локально в песочнице перед записью на реальное железо, выполните следующую команду (требуется файл UEFI-биоса `OVMF.fd`):

```bash
qemu-system-x86_64 -m 1024 -bios OVMF.fd -drive file=homeserver.img,format=raw
```

## 🔒 Безопасность и ограничения
* Учетная запись `root` **не имеет пароля** до тех пор, пока вы не зададите его при первом запуске через интерактивный мастер на физическом мониторе.
* В целях безопасности и сохранения минимализма **SSH-сервер в базовом образе отсутствует**.
